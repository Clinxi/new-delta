# 部署指南

## 1. 选择运行方式

| 方式 | 适合的情况 | 手机怎样连接 |
| --- | --- | --- |
| 现场电脑运行 | 彩排、内部活动、现场可统一 Wi-Fi | 与电脑处于可互通的局域网 |
| 公网服务器运行 | 嘉宾使用各自的移动网络 | 扫描指向 HTTPS 公网域名的二维码 |

局域网地址不会自动获得公网可达性。酒店 Wi-Fi 的客户端隔离、访客网络限制、电脑防火墙都可能阻止手机连接；以现场手机试扫结果为准。

## 2. 现场电脑运行

安装 Node.js 22.9 或更新版本（推荐 Node.js 24 LTS）。macOS 可直接双击项目根目录的 `启动.command`，脚本会自动安装缺少的依赖、首次创建 `.env`、保存随机主持口令并打开控制台，首次生成配置的端口为 `3188`。已有 `.env` 时沿用其配置；终端按 `Control + C` 停止。不要同时启动两个使用同一数据目录的服务。

终端手动运行方式如下，示例端口为 `3000`。若 `.env` 已存在，请直接编辑，不要覆盖：

```bash
npm install
cp .env.example .env
```

编辑 `.env`，至少设置主持口令：

```dotenv
ADMIN_PASSWORD=请替换为活动专用口令
PORT=3000
HOST=0.0.0.0
PUBLIC_URL=
```

然后运行：

```bash
npm start
```

打开 `http://localhost:3000/admin.html`（双击启动首次配置则为 `http://localhost:3188/admin.html`；以终端打印和 `.env` 为准），登录后检查手机入场地址。多网卡、VPN、虚拟机或网线与 Wi-Fi 同时连接时，自动选择的局域网地址可能不适合嘉宾；在控制台将公开访问地址改成手机实际可达的电脑地址，例如 `http://192.168.1.20:3000`。

公开访问地址使用完整的 `http://` 或 `https://` 源地址，不附加 `/stage.html`、`/join.html` 或查询参数。生效优先级为：`.env` 的 `PUBLIC_URL` → 控制台保存的公开访问地址 → 自动选择的局域网地址 → `localhost`。若 `.env` 已设置 `PUBLIC_URL`，应修改该值并重启，控制台保存的地址不会覆盖它。修改后重新展示二维码，并用手机验证。它仅决定链接内容，不会替你配置路由、防火墙或公网端口映射。

活动期间保持终端进程运行，关闭电脑自动休眠，并使用电源供电。若手机打不开页面，先检查两端网络和地址，再检查防火墙入站访问；不要将二维码中的地址改成 `localhost`。

## 3. 公网 HTTPS 部署

以下示例适用于已具备域名、Linux 服务器、TLS 证书和 Nginx 的环境。安装系统软件、申请证书和开放公网访问由部署人员完成，项目不会自动执行这些操作。

将项目复制到服务器固定目录，例如 `/srv/ceremony`，执行 `npm ci --omit=dev`。生产配置示例：

```dotenv
ADMIN_PASSWORD=请替换为足够长且不复用的口令
HOST=127.0.0.1
PORT=3000
PUBLIC_URL=https://launch.example.com
TRUST_PROXY=1
```

域名仅为占位示例，必须替换。HTTPS 在反向代理处终止，Node 服务只监听本机。`TRUST_PROXY=1` 仅适用于 Node 前方恰有一层可信代理，用于取得正确的 HTTPS 状态和客户端地址；有 CDN 等多层代理时，应先按实际拓扑改造信任规则。不要将 `.env`、参与者资料或主持口令放到静态资源目录 `public/`。

Nginx 的域名、证书路径按自己的环境修改：

```nginx
server {
    listen 443 ssl;
    server_name launch.example.com;

    ssl_certificate     /etc/letsencrypt/live/launch.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/launch.example.com/privkey.pem;

    client_max_body_size 1m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 1h;
    }

    location = /api/events {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 1h;
        gzip off;
    }
}
```

必须关闭 SSE 路径的代理缓冲，否则头像和人数可能延迟成批更新。如果域名前还有 CDN、网关或负载均衡，也需要允许长连接、禁用事件接口缓存和响应缓冲。该项目部署在域名根路径，示例不包含子路径重写。

配置生效后，在浏览器打开公网控制台，检查公开访问地址和二维码确实指向 HTTPS 域名。用一部关闭 Wi-Fi、只使用移动网络的手机入场，确认大屏能立即更新。

## 4. 保持服务运行：systemd 示例

创建只运行该项目的系统用户，并将项目和数据目录的读写权限赋给它。下面假设用户为 `ceremony`，Node 绝对路径为 `/usr/bin/node`；请按服务器实际安装位置修改。

`/etc/systemd/system/ceremony.service`：

```ini
[Unit]
Description=Interactive launch ceremony
After=network.target

[Service]
Type=simple
User=ceremony
Group=ceremony
WorkingDirectory=/srv/ceremony
Environment=NODE_ENV=production
ExecStart=/usr/bin/node --env-file=.env server.js
Restart=on-failure
RestartSec=3
UMask=0077
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

确认项目已提供 `.env` 并可正常启动后，由服务器管理员执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ceremony
sudo systemctl status ceremony
```

查看日志：

```bash
sudo journalctl -u ceremony -f
```

只启动一个服务实例。不要通过多个 Node 进程、PM2 cluster 或多个容器同时共享同一份 JSON 数据文件。需要高可用或多活动隔离时，应改造共享数据库、消息广播和文件存储。

## 5. 上线检查

- `.env` 中有活动专用主持口令，公开访问地址正确。
- 真实手机能够打开入场页并上传头像，头像在另一台电脑的大屏立即出现。
- 刷新大屏能恢复场次，短暂断网后能自动恢复状态。
- 倒计时、启动动画、Logo、中文文案在实际 LED 分辨率下清晰可见。
- 正式开放前已清空演示嘉宾，并更新二维码。
- 电脑供电、休眠设置、网络和备用人工启动口令已彩排。
- 已安排活动结束后的头像、昵称和备份清理责任人。

## 6. 升级与备份

活动进行中避免升级。需要备份或迁移时，先停止服务，再复制数据目录和 `.env` 至受控位置；升级后先在测试环境恢复并演练。备份包含参与者昵称、头像及活动状态，应按活动的资料保留约定处理。备份 `.env` 时也须保护主持口令。

## 本机隔离预览

开发和视觉验收可运行：

```bash
node scripts/preview.mjs
```

预览仅监听 `127.0.0.1`，默认端口 `3188`，固定演示口令为 `preview-ceremony-only`，数据写入 `.preview-data/`。它不能直接供会场手机访问，固定演示口令也不能作为正式活动口令使用。正式活动使用 `启动.command` 或 `npm start` 配合自己的 `.env`。如本机端口冲突，可先停止另一服务，或使用 `PREVIEW_PORT=3189 node scripts/preview.mjs`。

## 配置项速查

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `PORT` | `3000` | Node 监听端口 |
| `HOST` | `0.0.0.0` | Node 监听地址；反代部署建议 `127.0.0.1` |
| `ADMIN_PASSWORD` | 空 | 空值时每次启动随机生成；正式活动请固定独立口令 |
| `PUBLIC_URL` | 空 | 入场链接使用的根网址；优先于控制台保存值 |
| `DATA_DIR` | `./data` | 状态与头像目录 |
| `MAX_PARTICIPANTS` | `1000` | 软件参与人数上限，可配置为 1–5000 |
| `JOIN_RATE_LIMIT` | `2000` | 每个来源 IP 每分钟的入场请求上限；更新本人资料也计数 |
| `TRUST_PROXY` | `0` | 仅前方恰有一层可信代理时设为 `1` |

现场共用 Wi-Fi 时，多名嘉宾可能共享一个公网 IP。入场限频需考虑这一点；不要把软件人数上限理解为网络吞吐量或已实测并发容量。
